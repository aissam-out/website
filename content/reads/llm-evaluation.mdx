Classical NLP metrics answer a narrow question: how close is this output to a reference? LLM products usually need a different question: did the system do the job a user actually hired it for?

That split forces two layers of evaluation. Offline, you want a golden set of real tasks with expected outcomes: correct tool use, grounded answers, refusal when needed, schema-valid output. Online, you want product signals: resolution rate, escalation rate, latency, cost per successful task, and human review on the hard cases.

LLM-as-judge can help score open-ended answers at scale, but it is not a substitute for ground truth. Judges inherit bias, drift with prompt changes, and often reward fluent wrongness. Use them as a triage layer, not as the final authority.

The senior move is to evaluate the system, not only the model. A beautiful completion that retrieved the wrong document, skipped a required tool, or violated a policy is still a failure. If your dashboard only tracks BLEU-like fluency, you are measuring the wrong thing.
