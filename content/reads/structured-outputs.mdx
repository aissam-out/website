A conversational UI can tolerate messy prose. A booking API, a CRM write, or an agent tool call cannot. Structured outputs are how you make the model speak in contracts instead of vibes.

The practical pattern is to declare a schema (JSON Schema, tool arguments, or a typed object) and require the model to fill it. Constrained decoding and schema-aware APIs reduce the “almost valid JSON” tax that otherwise becomes a pile of brittle parsers and retries.

This is not only about formatting. A schema forces product decisions: which fields are required, which enums are allowed, what to do when the model is unsure. Those decisions belong in the interface, not in post-hoc string cleanup.

If your pipeline still depends on “extract the JSON from the markdown fence and hope,” you do not have structured generation yet. You have a parser fighting a probability distribution.
